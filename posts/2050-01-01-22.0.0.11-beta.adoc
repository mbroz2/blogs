== Jakarta Mail 2.1


1. Which Liberty feature(s) does your update relate to?
    
   Human-readable name (eg WebSockets feature): Jakarta Mail 2.1
   
   Short feature name (eg websockets-1.0): mail-2.1

2. Who is the target persona? Who do you expect to use the update? eg application developer, operations.

   Application developer, operations

4. Provide a summary of the update, including the following points:
   
   - A sentence or two that introduces the update to someone new to the general technology/concept.

   Jakarta Mail 2.1 support allows your Jakarta EE 10 applications to send, read, and edit E-Mail from mail servers via the Jakarta Mail APIs. 

   - What was the problem before and how does your update make their life better? (Why should they care?)
   
 The biggest change to Jakarta Mail 2.1 specification is the removal of the direct dependency of the specification APIs on the reference implementation. This means that in certain cases there will no longer be a need to compile your Jakarta Mail code against both the specification and the reference implementation (provided you aren't making any direct calls to the RI in your code). In order to facilitate this, Jakarta Mail 2.1 also introduced a utility interface [jakarta.mail.util.StreamProvider](https://jakarta.ee/specifications/mail/2.1/apidocs/jakarta.mail/jakarta/mail/util/streamprovider), that can be easily obtaining via the `jakarta.mail.Session.getStreamProvider()` method. You can then use the StreamProviders to obtain Encoded/Decoded Streams for any of the encoding/decoding methods mail-2.1 supports. 

   - Briefly explain how to make your update work. Include screenshots, diagrams, and/or code snippets, and provide a `server.xml` snippet.
   
The mail-2.1 feature can be enabled via the server.xml: 

```
  <featureManager>
    <feature>mail-2.1</feature>
  </featureManager>
```
   - Where can they find out more about this specific update (eg Open Liberty docs, Javadoc) and/or the wider technology?

More information about the Jakarta Mail 2.1 specification can be found at the [Jakarta Mail](https://eclipse-ee4j.github.io/mail/) project website.

== Jakarta EE 10: Support Jakarta Servlet 6.0


1. Which Liberty feature(s) does your update relate to?
    
   Human-readable name (eg WebSockets feature): 
>Jakarta Servlet 6.0
   
   Short feature name (eg websockets-1.0): 
>servlet-6.0

2. Who is the target persona? Who do you expect to use the update? eg application developer, operations: 
>Developers of Jakarta Enterprise Edition (EE) application.

3. Provide a summary of the update, including the following points:
   
   - A sentence or two that introduces the update to someone new to the general technology/concept.

>The Open Liberty servlet-6.0 feature is an implementation of the Jakarta  EE 10 Servlet 6.0 Specification.  It includes a number of new features, specification clarifications as well as deprecation features.
>
   - What was the problem before and how does your update make their life better? (Why should they care?)
>Prior to servlet-6.0, there were only a few specific methods that could be set for an application's cookie attributes. There was not an easy way for application to set a new attribute (for example, the recent browser security's SameSite attribute). One of the new features in servlet-6.0 is the ability to set any attribute using a Cookie's setAttribute method. In addition, servlet-6.0 also introduces some new request APIs to aid the application's debugging. Application developer can track or refer to a request using the ServletRequest's getRequestId or obtain details of the network connection that is being used by the request by calling ServletRequest's getServletConnection.

```
Examples:
 
Get an ID for this request:
    String id = ServletRequest.getRequestId();
Get a protocol that is used for this request:
    String protoId = ServletRequest.getProtocolRequestId();
Get ServletConnection object which has additional information for about the connection to this request:
    ServletConnection = ServletRequest.getServletConnection();
```
>
   - Briefly explain how to make your update work. Include screenshots, diagrams, and/or code snippets, and provide a `server.xml` snippet.
 
```
   <featureManager>
       <feature>servlet-6.0</feature>
   </featureManager>
```

>The Jakarta Servlet 6.0 Specification and Javadocs can be found at https://jakarta.ee/specifications/servlet/6.0/

== Open Liberty Instant On With Checkpoint and Restore


1. Which Liberty feature(s) does your update relate to?
    
   Human-readable name: Instant On Checkpoint feature
   
   Short feature name:  checkpoint-1.0 

2. Who is the target persona? Who do you expect to use the update? Application Developer, Operations

    application developers, operations

3. Write a paragraph to summarise the update, including the following points:
    
   - A sentence or two that introduces the update to someone new to the general technology/concept.

     Open Liberty InstantOn allows applications running on Open Liberty to checkpoint the startup process and restore the application process very quickly, providing InstantOn behavior for the application.
   - What was the problem before and how does your update make their life better? (Why should they care?)

     Starting an application can take several seconds and sometimes minutes before being able to service the applications first request.  Longer startup times inhibit an applications ability to scale to zero when deployed in a cloud environment such as Kubernetes.  Restoring an application from a checkpoint process can take much less time, up to 10 times faster than starting the Liberty application from the beginning.
   
   - Briefly explain how to make your update work. Include screenshots, diagrams, and/or code snippets, and provide a `server.xml` snippet.

     For details on how to use Open Liberty InstantOn have a look at the InstantOn beta blog at: https://ibm.biz/InstantOn
